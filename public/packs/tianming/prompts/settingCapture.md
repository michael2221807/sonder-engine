# 设定提取（setting_updates）

玩家本回合用 `<设定>…</设定>` 标记了长期设定。请在 JSON 中额外输出 `setting_updates` 数组，把标记内的内容**吃透并拆解**成结构化条目。

## 工作方法（必须遵守）

标记内容**可能是任意长度**——从一句话到一整段论述。你的任务：

1. **先通读吃透**：标记里包含几个独立的设定事实？（一个事实 = 一条关于人物/关系/世界的、值得长期记住的断言）
2. **逐个事实输出一条** `setting_update`：一句话概括该事实，配一小段原文出处。
3. 长段论述通常含 3~8 个事实；**宁可多拆几条短的，绝不输出一条长的**。修饰、举例、语气可以舍弃——保留会改变后续剧情的核心断言。

```json
{
  "setting_updates": [
    {
      "kind": "relationship",
      "statement": "林月是玩家的妹妹。",
      "evidence": "林月是我的妹妹",
      "anchors": ["林月", "妹妹"],
      "entities": ["林月", "玩家"]
    },
    {
      "kind": "character",
      "statement": "林月从小怕水。",
      "evidence": "她从小怕水",
      "anchors": ["林月", "怕水"],
      "entities": ["林月"]
    }
  ]
}
```

## 字段规则

- `kind`：只能是 `character`（人物）/ `relationship`（两个实体之间的关系）/ `world_fact`（世界事实）三者之一。
- `statement`：自包含的**一句话**，**不超过 200 字**（超过 240 字会被系统整条拒绝）。长段设定必须拆成多条，每条只说一件事。可以把代词解析成具体名字（"她" → "林月"、"我" → "玩家"），但**不得增加标记外的任何新信息**。
- `evidence`：**必须逐字取自 `<设定>` 标记内部的原文**，是 `statement` 的出处片段。只需**一小段**足以定位出处的原文（建议 10～60 字，**不超过 150 字**，超过 180 字会被拒绝），不要整段照抄。不得改写、不得跨越两个不同的 `<设定>` 段拼接。
- **JSON 安全**：`evidence` / `statement` 内若含英文双引号 `"`，必须写成 `\"` 转义，或直接选取不含引号的片段——未转义的引号会破坏整个 JSON 输出。（引号等标点差异不影响出处校验。）
- `anchors`：1-5 个激活词，用于后续检索命中；每个词必须在 `statement` 或 `evidence` 中出现过。
  - **必须是有辨识度的实词**（人名、地名、物名、具体特征），长度至少 2 个字。
  - **不要**用单字、也不要用「的/了/是/他/她/这个」这类常见虚词——它们几乎在任何句子里都出现，会让这条设定每回合都被无意义地注入。
- `entities`：0-2 个明确的实体名（人名/地名/物名），必须在 `statement` 或 `evidence` 中出现过；两个实体不得相同。

## 长段拆解示例

输入标记（节选）：

> `<设定>`这个世界实行"母畜条例"：适龄女性登记后按评分接受指派服务，报酬丰厚且享有升学就业优待；男性则承担更重的劳动，换取合法使用权。社会整体接受了这套规则，反对声音只剩细枝末节的争吵。`</设定>`

正确输出（一段拆成多条，每条一个事实 + 短出处）：

```json
{
  "setting_updates": [
    { "kind": "world_fact", "statement": "这个世界实行「母畜条例」：适龄女性登记后按评分接受指派服务。", "evidence": "适龄女性登记后按评分接受指派服务", "anchors": ["母畜条例", "评分"], "entities": [] },
    { "kind": "world_fact", "statement": "接受服务的女性报酬丰厚，并享有升学就业优待。", "evidence": "报酬丰厚且享有升学就业优待", "anchors": ["报酬", "优待"], "entities": [] },
    { "kind": "world_fact", "statement": "男性承担更重的劳动以换取合法使用权。", "evidence": "男性则承担更重的劳动，换取合法使用权", "anchors": ["男性", "使用权"], "entities": [] },
    { "kind": "world_fact", "statement": "社会整体接受母畜条例，反对声音仅剩细节争吵。", "evidence": "反对声音只剩细枝末节的争吵", "anchors": ["条例", "反对声音"], "entities": [] }
  ]
}
```

错误示范（会被系统整批拒绝）：把整段塞进一条 statement；或 evidence 整段照抄。

## 硬性约束

- **只提取 `<设定>` 标记内部的内容。** 标记外的行动、临时状态、疑问、假设、传闻、NPC 的谎言、以及你自己在正文里的发挥，一律不得进入 `setting_updates`。
- 一段标记可以拆成多条设定；本回合最多输出 10 条。
- 不要输出 `id`、`priority`、`enabled`、`op`、`confidence` 等任何其他字段——它们由系统决定。
- 本回合若没有 `<设定>` 标记，就不要输出 `setting_updates` 字段。
